# 비슷한 앱 비교와 참여 장치 판단 (2026-10-24)

최종 발표를 준비하는 고도화 단계에서 정리한 문서다. 노션 "피드백" 페이지의 세 토글(검정고시 독학 앱, 듀오링고, 열품타)을 바탕으로 했다.
팀 피드백 구현 경과는 `docs/superpowers/plans/2026-10-24-team-feedback.md`에 있다. 이 문서는 초기 비교와 이번 주 목표 개선 결정을 함께 정리한다.

## 1. 고졸 검정고시 모의고사 - 검정고시 독학 문제은행 (DAYLAB)

출처: [Google Play 앱 소개](https://play.google.com/store/apps/details?id=dev.daylab.geomjeong.go). 2026-10-24에 앱 설명을 읽고 정리했으며, 앱을 직접 설치해 보지는 않았다.

### 한 줄 비교

- **그 앱:** 문제은행·모의고사와 함께 취약 단원 분석과 FSRS 간격 반복 복습을 지원하는 독학 도구다.
- **배움길:** 선수 개념까지 내려가 확인한 기록을 멘토의 수업 준비로 연결하는 도구다.
- 경쟁하기보다 함께 쓸 수 있다. 발표에서는 이렇게 말할 수 있다: "배움길은 어떤 선수 개념부터 다시 확인할지 추천하고, 그 기록을 멘토의 다음 수업으로 연결합니다." 오답 원인을 확정적으로 밝혀냈다고 표현하지 않는다.

### 기능 비교

| 항목 | 그 앱 | 배움길 |
|---|---|---|
| 대상 | 혼자 공부하는 수험생 | 학교 밖 청소년 + 봉사 멘토 (+ 보호자) |
| 과목 | 필수 6과목 | 수학 (깊게) |

| 약점 찾기 | 과목·단원별 정답률 히트맵 | 영역 × 기초·선수·고졸 진단, 틀리면 하위 개념으로 추적 |
| 판정 방식 | 정답률 | 도움 없이 확인 / 혼자 다시 확인 / 보완 필요 |

| 사람 연결 | 1:1 문의 | 멘토 수업 준비, 활동일지, AI 코파일럿, 보호자 공유 |
| 편의 | 글자 크기, 다크 모드, 오프라인, 기기 동기화, 이어서 풀기 | 이어서 풀기, 큰 글씨 |

### 후속 검토 후보 (이번 수정 범위 아님)

1. **시험 D-day와 남은 기간에 맞춘 진도.** 시험 일정과 학습 계획을 연결할 후보이며 효과는 아직 검증하지 않았다.
   - "남은 보완 개념 12개 · 남은 8주"처럼 보여 주되, 개념마다 학습량과 선수 관계가 다르므로 개수만 나눈 진도를 강제하지 않는다. 멘토와 조정할 수 있는 참고 정보로 검토한다.
   - 시험 날짜는 앱이 정하지 않고 사용자가 직접 입력한다. 교육청 공고를 확인하라는 안내를 붙인다.
2. **시험 7일 전 체크리스트.** 쉽다. 시험장 경험이 적은 학생에게 도움이 된다.
3. **다시 확인할 때가 된 개념 알려 주기.** 중간 규모다.
   - 초기에는 고정 간격 복습 규칙(1일 → 3일 → 7일)을 후보로 검토한다. 학습 이력에 맞춰 간격을 조정하는 FSRS와는 구분한다. [FSRS 공식 설명](https://github.com/open-spaced-repetition/fsrs4anki)
   - '혼자 다시 확인' 상태를 '도움 없이 확인'으로 올리는 판정 원칙과 맞는다.
4. **오답 노트 자동 정리.** 중간 규모다. 각 문제에 "다시 확인할 선수 개념: ○○"을 함께 보여 주고 추정 근거를 연결한다.
5. **보기 지우며 풀기(소거법).** 쉽다. 멘토가 학생이 무엇을 지웠는지 보면 생각한 과정을 짐작할 수 있다.
6. **학습 캘린더.** 쉽다. 연속 일수 대신 쌓이는 숫자로 보여 준다.
7. **콘텐츠 안내 문구.** 아주 쉽다. 문제 출처, 정부 기관과 관계없음, 합격을 보장하지 않음을 적는다.

### 가져오지 않는 게 좋은 점

- **6과목 확장, 교시별 모의고사:** 문제를 만들고 검수하는 비용이 크다. 수학 개념 추적이라는 강점이 흐려진다.
- **푸시 알림, 기기 동기화, 오프라인:** 이번 범위에서는 보류한다. 동기화에는 사용자 연결·저장 구조가, 알림과 오프라인에는 별도의 전달·캐시 설계와 검증이 필요하다. 모든 기능이 일률적으로 로그인을 요구하는 것은 아니다.
- **정답률 하나로 판정:** '도움 없이 확인'이라는 차별점이 사라진다.

## 2. 듀오링고·열품타의 참여 장치

두 앱의 기능은 알려진 공개 기능을 기준으로 정리했다. 이번에 앱을 직접 설치해서 확인하지는 않았다.

### 듀오링고

| 장치 | 참여를 끌어내는 방식 | 배움길 적용 |
|---|---|---|
| 친구와 함께하는 연속 기록(불꽃) | 둘 다 해야 이어져서 서로 챙김 | 적용 안 함. 연속 기록 대신 주간 공동 목표를 선택 |
| 친구와 함께하는 주간 퀘스트 | 같은 목표를 나눠 채움 | **적용** (함께 목표의 원형) |
| 응원 보내기 | 버튼 하나로 가볍게 반응 | 함께 목표 안에 합침 |
| 매일 연속 학습일 | 끊기기 싫어서 매일 들어옴 | 적용 안 함 (매일 참여해야 한다는 부담을 줄이려는 설계 판단) |
| 리그·순위 | 경쟁 | 적용 안 함 (학생 간 비교·정보 공개를 줄이려는 설계 판단) |
| 하트 | 틀리면 줄어듦 | 적용 안 함 (틀린 답은 진단의 근거) |
| 푸시 알림 | 앱 밖에서 다시 부름 | 지금은 어려움 (서버 필요) |

### 열품타

| 장치 | 참여를 끌어내는 방식 | 배움길 적용 |
|---|---|---|
| 공부 타이머 | 공부를 시작하는 의식, 쌓인 시간이 보람 | 이번에는 뺌 (아래 판단 참고) |
| 공부 기록 달력(잔디) | 공부한 날이 쌓임 | 이번에는 뺌 |
| 그룹 '같이 공부 중' 표시 | 다른 사람을 보며 자극 | 실시간 표시는 서버가 필요해 나중에 함 |
| 하루 목표 시간 | 목표를 채우는 재미 | 함께 목표로 대신함 |
| 순위표 | 경쟁 | 적용 안 함 |
| 다른 앱 잠금 | 딴짓 차단 | 웹에서는 불가 |

## 3. 최종 판단: 무엇을 할까

처음에는 아래 네 가지를 추천했다.

1. 멘토·멘티 함께 목표 + 배움 불꽃
2. 응원 보내기
3. 공부 타이머 + 달력
4. 다시 왔을 때 반겨 주기

최종 발표 준비 시점을 기준으로 다시 따져 보면 넷을 다 하는 것은 좋지 않다.

판단 기준은 두 가지다.
- 5분 시연에서 심사위원에게 보이는가.
- 남은 시간에 확실히 끝낼 수 있는가.

| 항목 | 결정 | 이유 |
|---|---|---|
| 1. 함께 목표 + 불꽃 | **주간 목표만 구현** | 멘토 연결이라는 강점을 살린다. 불꽃·연속 기록은 제외하고 학생 학습 완료와 함께하는 수업 완료를 구분한다. 둘 다 채웠을 때 공동 완료를 표시한다. |
| 2. 응원 보내기 | **목표 카드에 통합** | 목표를 채우기 전부터 멘토가 배우는 과정에 응원할 수 있다. 공동 목표 완료 시에는 축하 문구를 보여 준다. 응원은 멘티에게 보이고, 보호자 전용 학습 안내와 별도로 저장한다. |
| 3. 타이머 + 달력 | **뺀다** | 오래 써야 숫자가 쌓여서 시연에서 보여 줄 것이 거의 없다. 정확히 재려면 멈춤 판정, 탭 이동 같은 예외 처리가 많다. 그런데 실력 판정에는 쓰지 않는 수치다. 발표에서 "다음 단계"로 소개한다. |
| 4. 다시 왔을 때 반겨 주기 | **새로 만들지 않는다** | '다음 학습' 카드와 '이어서 풀기'가 이미 같은 역할을 한다. 카드 문구만 다듬는다. |

### 구현 상태와 이번 개선

1. 피드백 수정 5건, AI 질문 힌트, 이번 주 함께 목표, 다음 학습 안내 문구는 구현했다.
2. 이번 개선은 **주간 집계·응원 조건·학생 성취 표시**에 집중한다. 타이머·달력·D-day·연속 기록은 추가하지 않는다.
3. 카드는 멘토 홈과 멘티의 진단 결과·학습 완료·대기 화면에 표시한다. 문제를 푸는 중에는 기존 화면을 유지한다.

#### 주간 집계와 기록 보존 기준

- 한국 시간 월요일 00:00부터 일요일까지, 현재 시각 이전의 응답을 집계한다.
- 등록 보충 묶음은 **이번 주 응답만으로 묶음 내 모든 문제를 정답 처리한 시점**이 있어야 인정한다. 지난주 답과 이번 주 일부 답을 합쳐 완료로 세지 않는다.
- AI 보충 연습은 이번 주 정답을 확인한 개념을 참여로 인정한다. 도움 받은 정답도 포함하며 숙달 판정과는 구분한다.
- 지난주 완료한 개념도 이번 주에 다시 조건을 채우면 인정한다. 같은 개념은 여러 번 풀거나 등록·AI 연습을 함께 해도 주당 한 번만 센다.
- 수업은 이번 주의 참여 회기만 센다. 결석·취소·미래 날짜는 제외한다.
- 학생 학습 2개를 채우면 수업 여부와 관계없이 **학생 학습 완료**를 표시한다. 수업 기록이 없으면 **함께하는 수업 대기**로 표시하며, 실제 일정이 없는데 예정이라고 단정하지 않는다.
- 두 조건을 모두 채우면 **함께 목표 완료**와 축하 안내를 표시한다. 진행 중에도 멘토가 최대 200자의 응원을 남길 수 있다.
- 기존 응답·진단·숙달·회기·일지·응원을 수정하거나 삭제하지 않는다. 저장 형식도 유지한다. 과거 기록에서 이번 주 참여 수를 다시 계산하므로 이전 화면과 숫자는 달라질 수 있다.

### 발표할 때 주의

- 참여율이 오른다고 단정하지 않는다. 검증한 근거가 없다.
- "꾸준히 참여하도록 이렇게 설계했다"는 의도 수준으로 말한다.
- 경쟁과 벌 대신 '함께'와 '응원'을 택한 이유는 참여 부담을 줄이고 멘토와 연결하려는 설계 판단으로 설명한다. 대상 학생 전체에게 경쟁이 해롭다는 검증 결과처럼 말하지 않는다.
- 팀원에게 학생 5명의 수학 멘토링 경험이 있다는 사실과, 이 참여 장치의 효과를 검증했다는 주장은 구분한다. 참여율·재방문 효과는 후속 사용 관찰로 확인해야 한다.
