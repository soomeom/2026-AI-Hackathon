# AI 보충 연습 구현·통합 검증

검증일: 2026-10-24 (한국 시간) / 브랜치: ver2 / 커밋·푸시 전

## 구현과 확인 위치

- 멘티: 첫 수준 확인 완료 또는 중간 결과 → 추천 개념 연습 / 로드맵 → **동류항 정리·일차식의 계산** → 해설과 보충 문제 풀기.
- 지원 개념은 최초 진입에 한 번 생성한다. 미제출 선택과 제출 결과는 복원하며, 새 생성은 ‘같은 개념 더 연습’에서만 한다.
- 멘토: 같은 브라우저에서 역할 변경 → 멘토 홈·학습 기록·수업 준비의 **AI 추가 연습**. 문항·학생 답·맞춤화 근거·해설·다음 수업 확인 사항을 본다.
- 멘토의 기존 AI 수업 제안은 기존 기출 학습 응답을 사용한다. AI 추가 연습을 기존 기출 근거나 진단 점수에 합산하지 않는다. AI 결과를 확인한 멘토가 수업 준비에서 관련 기출을 지정할 수 있다.
- 서버를 재시작해 팀원 시연 주소 `http://172.31.149.245:4173/`에도 새 `/api/practice`를 반영했다. 브라우저 기록은 초기화하지 않았다.

## 생성과 검증

Gemini가 식 구조·계수·오답 선택지를 제안하고, 공통 순수 모듈이 서버·브라우저에서 각각 계산한다. 발문과 해설은 검증한 구조에서 코드로 만든다.

- 허용: 정수·문자 x·덧셈·뺄셈·정수배. 깊이 최대 4, 노드 32, 리터럴 -12~12, 정수배 -9~9(0 제외), 최종 계수·상수 절댓값 50 이하, 문자 계수 0 제외.
- 정답 계수쌍을 독립 계산하고 모델이 주장한 정답과 대조한다. 선택지 네 개의 동치 중복과 정답 유일성을 확인한다.
- 생성 요청에는 작은 수 중심의 구조화 스키마를 사용한다. 현재 생성 문항은 양의 문자항 계수와 정수 상수 중심의 동류항 합, 괄호의 정수배·뺄셈을 다룬다. 검증기가 허용하는 모든 식 형태를 모델이 생성하는 것은 아니다.
- 같은 개념의 최근 등록 문항 응답 최대 3개만 참고한다. 이름·메모·전체 기록과 이전 AI 답변은 프롬프트에 넣지 않는다.
- 서버 5초 / 브라우저 6초, 자동 재시도 없음, 서버 동시 생성 4개. 사용자는 기다리는 중 기존 문제를 선택할 수 있다.
- 설정 없음·시간 초과·한도 초과·잘못된 JSON/수학·중복 문항은 등록된 같은 개념의 문제로 이어진다.

형식 제한은 [Gemini 구조화 출력](https://ai.google.dev/gemini-api/docs/structured-output)을 참고했다. 형식과 수학적 정답의 검증은 별도로 처리한다.

## 기록 보존

- 기존 저장 키와 schemaVersion 1 유지. generatedPractice에 문항·근거·선택 초안·결과를 별도 저장한다.
- 최초 진단·기출 경로·기출 정답률·독립 적용률·회기·일지를 다시 쓰지 않는다. AI 노출은 ai_review_practice로 분리한다.
- 역할·과목·메뉴 이동은 요청을 취소하고 늦은 응답을 무시한다. 생성된 문제와 제출 결과는 유지한다.
- 손상된 AI 레코드·배열·활성 참조만 원문과 함께 격리하며, 정상 진단 기록은 복원한다. 다른 탭의 revision 충돌에서는 최신 기록을 덮어쓰지 않는다.
- 중단했던 진단을 재개해도 과거 AI 기록을 유효하게 보존하도록 회귀 문제를 수정했다. 도움 표시가 다른 개념으로 넘어가는 문제도 수정했다.

### 실제 호출 소규모 점검

구조화 스키마 반영 후 가상 오답 입력으로 개념별 5회, 총 10회 점검했다. 원자료: [실측 JSON](ai-practice-live-check.json).

| 개념 | 검증 통과 | 시간 초과 | 검증 거부 |
|---|---:|---:|---:|
| 동류항 정리 | 2 | 2 | 1 |
| 일차식 계산 | 5 | 0 | 0 |
| 합계 | 7 | 2 | 1 |

통과한 호출은 1.609~4.140초였다. 이 10회는 생성 API 기술 점검이며 학습 효과·교육적 정확도·일반적인 성공률을 입증하지 않는다. 브라우저 점검에서는 추가 지연·거부도 관찰했다. 동류항 생성 안정성은 계속 보완할 여지가 있으며, 발표에서는 생성 성공을 보장한다고 설명하지 않는다.

초기 자유 JSON 안내에서는 유효 후보가 적었다. 검증 기준을 완화하지 않고 작은 수 중심의 구조화 스키마로 생성 범위를 제한했다. 실패 시 기존 문제 전환과 실제 제출·복원도 확인했다.

## 시연 순서와 한계

1. 첫 진단에서 수와 다항식의 본 문항→일차식→동류항까지 응답하고 중간 결과를 넘긴다.
2. 추천 개념 또는 로드맵에서 두 개념 중 하나를 연다.
3. AI 문제 또는 실패 대체된 기존 문제를 풀고 해설을 본다. AI/등록 문항 구분을 설명한다.
4. 새로고침 후 결과를 확인하고 멘토로 전환한다.
5. 멘토의 AI 추가 연습에서 답과 근거를 보고 다음 수업·관련 기출을 준비한다.

팀원 멘토의 실제 사용 의견과 학생 대상 효과 검증은 아직 확보하지 않았다. 계정 인증·DB·기기 간 동기화·다른 개념의 AI 생성은 이번 범위에 없다. 기존 일반 문제 풀이 화면과 독립 diagnostic.html은 유지했다.
