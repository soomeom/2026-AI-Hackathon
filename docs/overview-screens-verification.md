## 구성과 참고

[프로그래머스 코딩테스트 연습](https://school.programmers.co.kr/learn/challenges)의 공개 화면에서 메뉴, 간결한 목록, 문제 상세의 분리를 확인했다. 이 정보 구조를 참고해 배움길의 역할과 학습 흐름에 맞게 재구성했다. 로그인 후 대시보드를 조사하거나 디자인·코드를 복제한 것은 아니다.

- 멘토 홈: 진단 상태·남은 보충 연습·진행 중 학습, 가장 먼저 할 행동 하나, 상세 진입점 세 가지.
- 멘토 메뉴: 멘토 홈 / 로드맵 / 학습 기록 / 수업 준비 / 회기·일지. 첫 수업 확정·추가 문항 지정·AI 수업 제안은 수업 준비로 이동했다.
- 멘티 진단 결과: 추정 수준, 정답·오답·모름, 다음 추천 개념과 이유, 추천 연습 진입. 영역별 표와 응답 기록은 상세 보기로 분리했다.
- 일반 학습 완료·멘토 확인 필요: 이번 결과와 다음 학습 버튼, 접힌 상세 기록. 진행 중인 다른 문제가 없으면 로드맵을 연다.
- 문제 본문·선택지·힌트·즉시 피드백·채점·진단 판정과 저장 형식은 유지했다. 화면용 요약만 추가했으며 저장소 마이그레이션은 없다.

UI/UX 스킬의 가독성·초점·반응형 원칙을 적용했다. 검색 스크립트 결과는 이번 정보 구조와 직접 맞지 않아 참고 근거로 사용하지 않았다.

## 실제 브라우저 확인

검증용 주소 `http://127.0.0.1:13921/`의 기존 가명 학습 기록을 사용했다. 초기화하지 않았다.

1. 기존 진단 37문항(모름 37), 동류항 보충 완료, 남은 보충 36개를 새 홈과 결과에서 확인했다.
2. 홈에서 진단 상세를 열어 여섯 영역·응답 기록·결과 저장 기능을 확인했다.
3. 결과에서 추천 연습을 열어 기존 선택지·해설 화면과 `roadmap-title` 키보드 초점을 확인했다. 전체 로드맵 버튼으로 실제 지도에 돌아왔다.
4. 수업 준비에서 ‘괄호가 있는 일차방정식의 풀이’를 첫 수업으로 지정했다. 멘티로 전환해 기존 풀이 화면에서 본문항과 새 문제를 풀고 완료 요약을 확인했다. 새로고침 후에도 완료 결과가 복원되고 로드맵 버튼이 작동했다.
5. 모바일 390×844 설정(스크롤바 제외 본문 375px)에서 멘토 홈·진단 결과 모두 가로 넘침이 없었다. 추천 버튼 높이는 48px였다. 검증 후 화면 크기 설정을 복원했다.

독립 리뷰에서 발견한 추천 연습 종료의 목적지 불일치와 진입 초점 누락을 수정했다. 완료 화면 통합 테스트도 실제로 표시된 버튼을 클릭하도록 보완했다.
