## 1. 시작 화면: 멘티 버튼을 카드 위 갈색과 통일

- 현재: 멘티 카드는 위 테두리와 아이콘이 갈색(`--accent`)인데, 버튼만 초록 테두리(`styles.css:330-331` `.entry-learner > button`).
- 수정: 멘토 버튼과 같은 채움형으로, 색만 `--accent` 계열로 바꾼다. 글자는 흰색, hover는 한 단계 진한 갈색.
- 확인: 흰 글자 대비 4.5:1 이상인지 계산한다(부족하면 진한 갈색 토큰 `--accent-ink`를 추가한다).
- 보호자 카드(다른 세션이 추가)도 같은 규칙(카드 색 = 버튼 색)인지 맞춰 본다. 그 카드의 색은 다른 세션이 정한다.
- 파일: `public/styles.css`

## 2. 진단 결과 화면: 버튼이 버튼처럼 보이게

- 현재: "맞춤형 학습 로드맵 보기", "영역별 결과·응답 기록", "중단한 수준 확인 이어서 풀기"가 `button.ghost`라서 테두리와 배경이 없다(`styles.css:88`). hover 전에는 글씨와 구분이 안 된다.
- 수정:
  - 보조 버튼 스타일 `button.secondary`를 새로 만든다. 흰 배경, 1px 선, 오른쪽 화살표, 최소 높이 44px.
  - 위 두 링크(`learning-overview.js:24`)와 멘토 쪽 같은 버튼(`initial-assessment.js:146,149`)을 `secondary`로 바꾼다.
  - "중단한 수준 확인 이어서 풀기"(`initial-assessment.js:79`)는 진단을 멈춘 학생에게 가장 중요한 행동이므로 `primary`로 바꾸고, 결과 요약 바로 아래로 올린다.
  - `ghost`는 "닫기", "← 돌아가기"처럼 덜 중요한 동작에만 남긴다.
- 파일: `styles.css`, `learning-overview.js`, `initial-assessment.js`, `overview.css`
- 테스트: 해당 버튼의 class를 확인하는 단언을 추가한다.

## 3. 멘토 수업 준비: 지정한 문제 목록 + 지정 취소

- 현재: "추가 문제 지정"(`mentor.js:39`)은 지정만 할 수 있다. 지정한 목록은 '학습 기록' 탭의 경로 목록에만 있고, 취소 기능은 없다. 과제는 `{ status: 'assigned' }`로 저장된다(`store.js:41`).
- 수정:
  - 수업 준비 카드 아래에 "지정한 문제" 목록을 보여 준다. 문제 요약, 지정 시각, 상태(풀기 전 / 푸는 중 / 완료)를 표시한다.
  - 모든 지정 문제에 "지정 취소" 버튼을 둔다. **이미 풀기 시작한 문제도 취소할 수 있다.** (결정: 급한 사정으로 중간에 그만둘 수 있어야 한다.)
    - 지우지 않고 `status: 'canceled'`, `canceledAt`, `startedBeforeCancel`(취소 전에 응답이 있었는지)을 기록한다. 연결된 경로는 학생 화면과 다음 문제 후보에서 뺀다.
    - 풀기 시작한 문제를 취소할 때는 확인 문구를 보여 준다: "학생이 풀던 문제예요. 지금까지의 응답은 기록에 남아요."
    - 취소 후 목록에는 "풀다가 취소됨 · 응답 N개 기록 유지" 표시를 남긴다. 아직 안 푼 문제는 "풀기 전 취소됨"으로 표시한다.
    - 이미 남은 응답은 지우지 않는다. 개념별 근거로 계속 쓴다(근거 자료 보존).
  - store에 `cancelAssignment({ assignmentId })`를 추가하고, 이벤트 `assignmentCanceled`를 남긴다. 학습 엔진에 경로 중단 명령이 없으면 `update()`로 과제 상태만 바꾸고, 경로 쪽에서는 과제 상태를 보고 숨긴다.
  - 취소는 되돌릴 수 있어야 한다. 취소된 줄에 "다시 지정" 버튼을 두며, 새 경로로 다시 시작한다.
  - 표시가 예상보다 복잡하면 줄인다. 그 경우 상태 표시 없이 취소만 되게 한다(결정된 대체안).
- 영향 확인: 멘토 홈 흐름도의 "문제 지정 N개"(`learning-overview.js:57`), 학생의 다음 문제 선택, 보호자 요약(다른 세션)이 취소된 과제를 세지 않는지 확인한다.
- 파일: `store.js`, `mentor.js`, 학생 문제 목록, 관련 테스트
- 테스트:
  - 풀기 전 취소 → 목록에 '풀기 전 취소됨', 학생 화면에서 빠짐
  - 풀던 중 취소 → '풀다가 취소됨 · 응답 N개', 응답과 근거는 그대로 남음
  - 다시 지정 → 새 경로 생성
  - 새로고침 후에도 유지

## 4. 멘토 로드맵: "해설과 보충 문제 풀기" → "문제·정답·해설 보기"

- 현재: `roadmap-page.js:17`의 `canPractice`가 역할과 상관없이 정해진다. 그래서 멘토도 학생용 풀이 버튼(`concept-map.js:80`)을 본다. 누르면 멘토가 문제를 푸는 화면으로 간다.
- 수정:
  - 멘토일 때는 패널 하단 버튼을 "문제·정답·해설 보기"로 바꾼다.
  - 누르면 같은 패널 안에서 보충 문제마다 펼침(`<details>`)을 연다. 문제, 정답, 풀이 단계(`solutionSteps`)와 학생의 응답 결과를 보여 준다.
  - 문제 목록의 각 줄을 눌러도 같은 펼침이 열리게 한다. 학생일 때는 지금처럼 풀이 화면으로 간다.
  - 멘토 화면에서는 응답이 기록되지 않는다. 멘토가 실수로 학생 기록을 만들 수 없다.
- 관계 지도(`relation-map.js:139`)도 같은 `lessonPanel`을 쓰므로 함께 바뀐다.
- 파일: `concept-map.js`, `roadmap-page.js`, `roadmap.css`
- 테스트: 멘토 렌더 결과에 '풀기' 버튼과 `data-roadmap-action="open"`이 없고, 정답과 해설이 있다 / 학생 렌더는 그대로다.

## 5. 학생 로드맵: 전체 보기 팝업 스크롤

- 원인:
  - `.map-overview-panel`은 grid이고 `max-height`와 `overflow:hidden`이 걸려 있다.
  - 그런데 행 높이가 `auto`라서 오른쪽 칸(`.map-overview-chapters`)이 내용만큼 커진다. 그래서 칸 자체의 `overflow-y:auto`가 동작하지 않고, 아래가 잘린다(`roadmap.css:134,140`).
- 수정:
  - `.map-overview-panel`에 `grid-template-rows:minmax(0,1fr)`를 준다.
  - 모바일(두 줄 배치)에는 `auto minmax(0,1fr)`를 준다.
  - 제목과 범례는 스크롤해도 위에 남도록 `position:sticky`를 검토한다.
- 확인: 데스크톱 높이 700px, 모바일 390×700에서 6번 영역 끝까지 스크롤된다. 바깥 페이지는 스크롤되지 않는다.
- 파일: `roadmap.css`

## 6. 완료한 개념에 "도장 쾅" 표시 — 보류 (작성한 팀원이 방향을 정하는 중)

아래는 참고용 초안이다. 팀원의 안이 나오면 그 안을 따른다.

- 피드백 위치: 관계 지도 캡처 바로 아래에 "완료한 퀘스트는 도장 쾅 표시로 하기"라고 적혀 있다.
- 앱에는 '퀘스트' 기능이 없다. 그래서 **보충 연습을 끝낸 개념(현재 작은 ✓ 배지, `relation-map.js:120`)**을 도장으로 바꾸자는 뜻으로 해석했다. 작성자에게 확인이 필요하다.
- 수정안:
  - 작은 ✓ 배지 대신, 노드에 살짝 기운 원형 도장("완료")을 찍는다.
  - **처음 완료한 순간에만** 도장이 찍히는 애니메이션을 0.3초 재생한다. 커졌다 줄어드는 동작이다.
  - 이미 본 도장은 다시 재생하지 않는다. 본 개념 id를 localStorage에 기록한다.
  - `prefers-reduced-motion`이면 애니메이션 없이 도장만 보여 준다.
  - 학생 경로(`concept-map.js` 점 `✓`)와 전체 보기 팝업의 점에도 같은 모양을 쓴다.
- 주의:
  - 도장 색은 상태 색(초록/보라/주황)과 겹치지 않게 한다.
  - "보충 연습 완료"는 진단 판정이 아니라는 기존 원칙을 지킨다. 그래서 '숙달' 같은 말은 쓰지 않는다.

## 7. AI 힌트 — 답 대신 질문 (결정: 넣는다)

- 동작: 학생이 보충 문제에서 "힌트 받기"를 누르면, AI가 정답을 말하지 않고 다음 단계로 이끄는 질문을 하나 준다. 최대 3단계까지 준다.
- 기존 구조를 다시 쓴다. `/api/ai` + `validateAIInput/validateAIOutput`에 작업 종류 `hint`를 추가한다.
- 안전장치(코드에서 검사):
  - 응답에 정답 값, 정답 보기 번호·내용이 들어 있으면 버린다.
  - 버리면 미리 쓴 기본 힌트(`solutionSteps` 첫 줄을 질문형으로 바꾼 것)를 대신 보여 준다.
- 기록: 힌트를 본 문제는 "도움 받고 맞힘"으로 남긴다. 기존 '도움 없이 확인' 판정을 부풀리지 않는다.
- 규모: 서버 계약, 화면, 테스트를 합쳐 반나절 정도.

## 8. (미정) 손글씨 풀이 사진 분석

- 사진 업로드, Gemini 이미지 입력, 처음 틀린 줄 찾기, 개념 후보 목록 안에서만 고르기, 멘토 확인 화면이 필요하다.
- 그래서 규모가 가장 크다. 또한 **학생 손글씨 사진이 외부 AI로 나간다.** 개인정보 안내와 동의 화면이 필요하다.
- 1~5번과 7번을 마친 뒤 남은 시간을 보고 정한다. 넣는다면 범위를 줄인다.
  - 객관식이 아닌 문제 1~2개에만 적용한다.
  - 결과는 멘토 화면에 '추정'으로만 보여 준다.
  - 사진은 서버에 저장하지 않는다.
- 시간이 모자라면 최종 발표에서 "다음 단계 계획"으로 소개한다.

## 9. 참여 장치: 멘토·멘티 이번 주 함께 목표 (결정: 작게 넣는다)

- 근거: 듀오링고와 열품타의 참여 장치를 비교한 결과다. 비교와 판단의 자세한 내용은 `docs/baeumgil/engagement-benchmark.md`에 있다.
- 범위:
  - 학생 홈과 멘토 홈에 "이번 주 함께 목표" 칸을 하나 둔다. 예: 보충 개념 ○/2 · 수업 ○/1.
    - 학생 몫은 보충 연습을 마친 개념 수로 센다.
    - 멘토 몫은 그 주에 기록한 회기 수로 센다.
  - 목표를 다 채우면 완료 표시를 보여 준다. 도장 모양은 6번(팀원 안)이 정해지면 그 안을 따른다.
  - 멘토는 완료된 목표에 응원 한마디를 남길 수 있다. 응원은 학생 홈의 보호자 응원과 같은 자리에 보여 준다.
- 만들지 않는 것:
  - 불꽃 개수와 연속 기록. 몇 주가 쌓여야 의미가 있고, 시연에서는 가짜 기록이 필요하다.
  - 따로 만드는 응원 버튼.
  - 공부 타이머와 달력.
  - 순위, 하트, 푸시 알림.
- 기존 것을 다듬는 것: "다시 왔을 때 반겨 주기"는 '다음 학습' 카드 문구를 한 줄 다듬는 것으로 대신한다.
- 발표 문구: 참여율이 오른다고 단정하지 않는다. "꾸준히 참여하도록 이렇게 설계했다"는 의도 수준으로 말한다.
