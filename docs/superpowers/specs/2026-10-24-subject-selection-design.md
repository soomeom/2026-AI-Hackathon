# 시연용 과목 선택 설계안

상태: 사용자 승인 후 구현·통합 검증 완료. 실행 결과는 ../plans/2026-10-24-subject-selection.md 참조.
기준: ver2 `3aadeaa`, 2026-10-24.

## 1. 필요성 판단과 현재 구현

과목 선택은 아직 없다. 수학 시연의 필수 조건은 아니지만, 어떤 과목을 지원하는지 보여 주고 입장 흐름을 완성하는 데 유용하다. 이번 변경은 실제로 준비된 수학 학습과 준비 중인 과목을 구분하는 화면·진입 로직으로 제한한다.

- `apps/baeumgil/public/src/state/demo-session.js`: 역할만 저장한다. 과목 선택 상태가 없다.
- `apps/baeumgil/public/app.js`: 역할을 고르면 즉시 멘토 또는 멘티 화면을 연다.
- `apps/baeumgil/public/src/ui/mentor.js`: 고졸·중졸·자체 제작은 문항 분류이며 과목 선택이 아니다.
- `apps/baeumgil/public/src/ui/text.js`: 학생 정보와 문항 출처가 수학으로 고정되어 있다.
- `apps/baeumgil/public/src/ui/sessions.js`: 회기 요약에 수학 학습 문구를 사용한다.
- `apps/baeumgil/public/src/learning/initial-assessment.js`: 학생별 적응형 수학 진단을 사용한다.
- 기획서의 해커톤 집중 범위도 고졸 검정고시 수학이다. 이번에 다른 과목의 진단·문제은행까지 확장할 필요는 없다.

## 2. 확정 범위와 제안하는 기본값

사용자 확정: **수학만 학습 가능, 다른 과목은 준비 중. 이번에는 계획 먼저.** 기존 역할 변경 시 학습 기록 보존 요구도 유지한다.

아래는 설계자가 제안하는 기본값이며 사용자 확정 사항과 구분한다.

- 멘토와 멘티 모두 역할 선택 다음에 같은 과목 선택 화면을 본다.
- 표시 순서: 수학, 국어, 영어, 사회, 과학, 한국사. 이는 시연 화면의 목록이며 공식 시험 전체 과목 목록을 뜻하지 않는다. 선택과목·시험 종류 선택은 이번 범위 밖이다.
- 수학 카드만 진입 버튼이 있다. 다른 카드는 `준비 중`과 `아직 학습할 수 없어요`를 표시하고 실행 버튼을 만들지 않는다. 색상만으로 상태를 구분하지 않는다.
- 헤더의 `과목 선택`은 현재 역할을 유지하고 과목 화면으로 돌아간다. `역할 바꾸기`는 역할 입장 화면으로 돌아간다.
- 수학으로 돌아오면 멘토는 오늘 할 일, 멘티는 기존 지정 학습 또는 첫 수준 확인으로 들어간다. 세부 탭 위치까지 복원하지는 않는다.

## 3. 화면과 이동 규칙

```text
역할 입장
  ├─ 멘토로 체험하기 → 과목 선택 → 수학 → 멘토 오늘 할 일
  └─ 멘티로 체험하기 → 과목 선택 → 수학
                                  ├─ 기존 지정 학습 있음 → 이어 풀기
                                  └─ 지정 학습 없음 → 첫 수준 확인 / 결과·대기

학습·멘토 화면 → 과목 선택 → 현재 역할로 수학에 다시 입장
어떤 역할 화면에서든 → 역할 바꾸기 → 역할 입장
```

과목 화면 제목은 `어떤 과목을 함께 배울까요?`, 안내는 `지금은 수학을 체험할 수 있어요. 다른 과목도 준비하고 있어요.`로 한다. 수학 버튼은 `수학 학습 시작`(멘티), `수학 지도 시작`(멘토)으로 구분한다. 카드에는 `학습 가능`을 표시하며, 기존 기록이 있으면 `기존 학습 기록을 이어갈 수 있어요`라고 안내한다.

과목 화면에서도 현재 가명 프로필·역할을 보여 준다. 수학 작업 화면에서는 역할과 함께 `수학`을 표시한다. 초기화는 수학 작업 화면에서만 기존 두 번 확인 방식으로 제공한다. 역할 입장·과목 선택 화면에는 초기화 버튼을 표시하지 않는다.

## 4. 상태·저장과 호환성

별도 URL이나 라우터를 추가하지 않고 기존 앱 화면 분기를 확장한다.

| 입장 상태 | 화면 |
| --- | --- |
| 역할 없음 | 역할 입장 |
| 유효한 역할 + 과목 없음 | 과목 선택 |
| 유효한 역할 + `subjectId: math` | 해당 역할의 기존 수학 작업 화면 |

선택 상태는 기존 `sessionStorage`의 `baeumgil:demo-session:v1` 객체에 선택 필드 `subjectId`를 추가한다. `version: 1`과 역할 검증을 유지한다. 학습 `localStorage`의 키·스키마·ID·기록 내용은 변경하지 않는다.

- 역할 선택: 역할 저장, 과목은 null. 과목 화면으로 이동한다.
- 수학 선택: 역할이 있을 때만 `subjectId: math`를 저장하고 기존 입장 준비 함수를 실행한다.
- 과목 선택으로 돌아가기: 역할 유지, 과목만 null로 저장한다.
- 역할 바꾸기: 역할·과목을 모두 지운다. 다시 역할을 고르면 과목 화면부터 시작한다.
- 새로고침: 역할·수학이 저장되어 있으면 작업 화면, 역할만 있으면 과목 화면을 복원한다.
- 기존 버전의 역할만 저장된 탭: 그 역할을 유지하면서 새 과목 화면으로 들어간다.
- 손상된 역할: 역할 입장. 잘못된 과목·준비 중 과목: 유효한 역할은 유지하고 과목 화면으로 복귀한다. 수학으로 자동 치환하지 않는다.
- 과목 ID는 UI 클릭뿐 아니라 저장·진입 함수에서도 허용 목록으로 검사한다. 준비 중 과목은 선택 상태에 기록할 수 없다.
- 저장 불가 환경: 페이지 안에서 선택은 가능하고 새로고침 시 유지되지 않는다는 기존 안내를 확장한다.
- 새 탭은 역할 입장부터 시작한다. 브라우저의 탭 복제는 sessionStorage를 복사할 수 있다는 기존 한계가 유지된다.
- 초기화 후에는 현재 역할·수학 선택은 유지하며 학습 기록만 기존 규칙대로 초기화한다.

현재 모든 학습 기록은 수학 범위이다. 이번에는 기록에 과목 필드를 일괄 추가하거나 여러 과목 저장소를 만들지 않는다. 실제 두 번째 과목을 활성화할 때 과목별 문항·진단·요약·AI 입력·회기 집계를 분리하는 별도 설계가 필요하다.

## 5. 기록 보호와 작업 종료

기존 `leaveRole`의 보호 절차를 과목 화면 이동에도 재사용한다.

1. 멘토의 저장하지 않은 회기 입력이 있으면 손실 경고를 먼저 표시한다. 취소하면 역할·과목·현재 폼·AI 요청을 그대로 둔다.
2. 이동이 확정되면 진행 중인 AI를 취소하고 요청 ID를 무효화한다. 늦게 온 응답이 결과를 저장하지 못하게 한다.
3. 입장 상태를 변경하고 멘티 풀이 시간을 중단한다. 과목 화면에서 보낸 시간은 풀이 시간에 포함하지 않는다.
4. 새 화면을 표시하고 제목 또는 주 콘텐츠로 키보드 초점을 이동한다.

기존 학습 응답, 노출 이력, 진단 응답, 경로, 회기, 확정 일지를 보존한다. 일지 초안은 기존처럼 페이지 메모리에 유지한다(새로고침 보존은 아님). 진단 응답도 수학으로 재입장할 때 이어진다. 기존 과제가 있으면 현재 입장 규칙에 따라 과제를 먼저 열고 진단은 기존 버튼으로 다시 볼 수 있다.

## 6. 구현 시 작업 순서와 파일 범위

이 절은 승인 후 구현 순서를 위한 개요다. 이번 단계에서 제품 코드·테스트 코드는 변경하지 않는다.

1. **과목 목록과 입장 상태**: `public/src/content/subjects.js`를 새로 만들어 과목 ID·이름·활성 여부를 관리한다. `public/src/state/demo-session.js`에 과목 선택·선택 해제와 기존 저장본 호환 규칙을 추가한다. 역할·과목이 잘못된 경우를 포함한 상태 테스트부터 작성한다.
2. **과목 선택 화면**: `public/src/ui/subject-selection.js`를 추가한다. 기존 카드·색상·버튼 스타일을 재사용하고 모바일에서는 카드를 세로로 배치한다. 준비 중 과목에는 실행 가능한 진입 동작을 연결하지 않는다.
3. **앱 연결·보호 절차**: `public/app.js`, `public/index.html`, `public/styles.css`를 수정한다. 역할 선택과 실제 수학 화면 입장을 분리한다. `syncVisibility`는 역할뿐 아니라 수학 작업 화면 여부까지 확인한다. 과목 변경·역할 변경에 회기 입력 경고, AI 취소, 초안 보존을 함께 적용한다. AI 취소 안내는 역할/과목 이동 모두에 맞는 문구로 바꾼다.
4. **통합 검증·문서**: 기존 `tests/demo-entry*.test.js`의 즉시 입장 기대를 두 단계 흐름으로 갱신하고 `tests/subject-selection.test.js`를 추가한다. README와 시연 순서를 갱신한다. 구현 전후 다른 세션과 대상 파일이 겹치는지 확인하고 겹치면 대기한다.

변경하지 않을 영역: 수학 문제은행, 채점·보충 경로, 적응형 진단 알고리즘, 학습 데이터 스키마, AI 출력 계약, 실제 인증·서버 저장.

## 7. 완료 기준

- 두 역할 모두 과목 화면을 거쳐 수학으로 정상 입장한다.
- 준비 중 카드와 임의 과목 ID로 학습에 진입할 수 없다.
- 기존 역할만 있는 저장본, 잘못된 과목, 저장 불가, 새로고침, 새 탭 동작이 위 표와 일치한다.
- 진단 한 문항 응답 → 과목 화면 → 수학 재입장 시 응답이 남는다. 기존 과제의 답안·도움 기록도 유지된다.
- 멘토 회기·확정 일지·작성 중인 초안이 과목 이동으로 지워지지 않는다.
- 저장하지 않은 회기 경고를 취소하면 현재 입력·화면이 유지된다.
- 과목 화면 체류 시간이 풀이 시간에 더해지지 않고, 취소를 무시한 늦은 AI 응답도 저장되지 않는다.
- 수학 선택 전에는 학습 문제 노출이나 진단 시작을 자동으로 발생시키지 않는다.
- 초기화 확인은 과목/역할 이동 시 해제되어 실수로 두 번째 클릭이 이어지지 않는다.
- 전체 테스트·콘텐츠 검사 통과, 실제 브라우저에서 진단→멘토 지정→멘티 풀이 확인, 모바일 가로 넘침 없음, 키보드 입장 가능.

## 8. 검토 상태

사용자가 정한 범위에 맞춘 설계이며, 이후 사용자가 위 설계대로 구현을 승인했다. 화면 위치·이동 규칙은 위 기본값으로 구현했다.

독립 설계 검토 결과: 구현 계획 수립을 막는 미해결 질문 없음. 기록·초안 보존, 과목 화면 체류 시간 제외, 늦은 AI 응답 차단, 기존 역할 저장본 호환 규칙이 현재 코드 구조와 일치함을 확인했다. 이번 변경은 설계 문서 한 개이며 제품 코드 변경은 없다.
