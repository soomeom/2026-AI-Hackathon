# AI 보충 문제 생성 설계

작성일: 2026-10-24 / 대상: ver2 / 상태: 검토용 설계, 구현 전

## 목표와 적용 범위

학생의 진단·보충 오답 기록을 참고해, 현재 학습할 선수 개념에 맞는 새 연습 문제를 만든다. 첫 적용 범위는 `roadmap-linear-sum`(일차식의 계산)과 `roadmap-like-terms`(동류항 정리) 두 개념이다. AI 문제는 코드로 검증한 뒤에만 출제하며, 생성할 수 없으면 해당 개념의 기존 등록 문제를 제공한다.

사용자가 승인한 방향은 두 개념 우선 적용, 정답 검증, 실패 시 기존 문항 대체, 기존 진단 신뢰도 유지다. 아래의 진입 방식·시간 제한·데이터 계약은 구현을 위한 제안이며 아직 최종 승인된 제품 결정은 아니다.

### 첫 구현에서 하는 일

- ver2 메인 앱의 진단 완료/중간 결과 이후 로드맵 보충 학습에 적용한다. 멘티·멘토가 같은 저장 기록을 본다.
- 해당 두 개념의 보충 문제를 열면 AI 문제 한 개를 준비한다. 같은 화면을 다시 그렸다는 이유로 재요청하지 않는다.
- 생성 대기 중에도 `기존 문제로 바로 연습`을 선택할 수 있다.
- 검증된 생성 문항, 실제 풀이, 출처, 원래 진단과의 연결을 저장하고 새로고침 후 복원한다.
- 기존 수학 문제 화면의 선택지·제출·해설 구조를 재사용한다.

### 유지하거나 다음으로 미루는 일

- 첫 수준 확인의 고졸·선수·기초 문항과 연결 관계는 현재 검수 문항을 유지한다. 진단 도중 AI 문제로 교체하지 않는다.
- 일반 기출 과제의 `engine.js` 단계 전이, 기출 재도전과 새 문제 확인은 이번 범위에서 바꾸지 않는다.
- 별도 `diagnostic.html`은 기존 문제은행 방식으로 유지한다. 공통 UI 변경으로 이 화면이 깨지지 않도록 검사한다.
- 분수·소수·방정식 풀이·문장제·도형·다른 개념은 제외한다.
- AI가 선수 관계나 학년·수준을 새로 판정하지 않는다. AI 연습 정답을 최초 진단 통과나 독립 숙달로 승격하지 않는다.

## 현재 코드에서 확인한 제약

- `public/src/learning/diagnostic.js`: 등록 문항의 `prerequisite_question_ids`를 따라 진단한다.
- `public/src/learning/initial-assessment.js`: `openInitialRoadmap`/`answerInitialRoadmap`가 카드의 등록 `questionIds`만 허용한다.
- `public/src/learning/roadmap.js`: 등록 문제의 정답 기록으로 기존 `practiceComplete`를 계산한다.
- `public/src/ui/roadmap.js`: 전달된 문제은행에서 현재 문제 ID를 찾아 표시한다.
- `server/ai-provider.mjs`: 현재 Gemini 수업 제안·활동일지용 계약에 결합되어 있다.
- `public/src/state/persistence.js`: 저장 스키마와 revision 충돌 검사로 기존 기록을 보호한다.
- 현재 작업 폴더에는 LAN 서버 설정과 HTTP ID 생성 오류 수정이 미커밋 상태로 있다. 구현 착수 시 다른 세션 활동과 변경 내역을 다시 확인하고 그대로 보존한다.

## 선택한 방식과 대안

권장 방식은 **AI가 제한된 수학 구조와 선택지 후보를 만들고, 코드가 독립 계산·검증·화면 문장·해설을 확정하는 방식**이다.

자유로운 문제·해설 텍스트를 그대로 받으면 두 식이 같은지, 발문과 정답이 맞는지 확실히 검증하기 어렵다. 반대로 코드가 숫자만 무작위로 바꾸는 것은 현재 템플릿 생성과 차별점이 작다. 따라서 AI가 실제 관찰된 오답에 맞춰 식의 구조·계수·오답 후보를 제안하되, 표시되는 수학 내용은 검증 가능한 구조로 한정한다. 발표에서도 ‘자유로운 수학 문제를 모두 검증한다’고 설명하지 않는다.

## 사용자 흐름

1. 기존 진단 완료 → 로드맵 → 두 개념 중 하나의 보충 연습 열기.
2. 같은 진단·개념의 활성 AI 문항이 있으면 ready/answered 상태를 그대로 복원한다. 활성 참조가 없으면 그 개념의 미제출 문항, 없으면 최근 제출 문항을 연다. 해당 진단·개념에 AI 문항이 전혀 없는 최초 진입에서만 자동으로 한 번 생성한다. 이후 새 생성은 ‘같은 개념 더 연습’을 명시적으로 누를 때만 한다.
3. `지금 연습할 개념에 맞는 문제를 준비하고 있어요`와 `기존 문제로 바로 연습`을 표시한다.
4. 서버·브라우저 양쪽 검증을 통과하면 `AI 맞춤 연습 · 정답 검증 완료` 표시와 함께 한 문제를 연다. 기출로 표시하지 않는다.
5. 기존 방식으로 선택·모름·제출 후 코드가 계산한 풀이를 보여 준다.
6. 제출 뒤 `같은 개념 더 연습`은 새 요청 한 번, `로드맵으로 돌아가기`는 기존 화면으로 이동한다. 재렌더·새로고침만으로 재생성하지 않는다.
7. 실패·미설정·시간 초과 또는 사용자의 기존 문항 선택 시 `준비된 연습 문제로 이어갈게요`라고 안내하고 연결된 기존 문제를 연다.

첫 버전의 AI 연습은 **추가 연습 기록**이다. 기존 등록 문제의 완료 수/분모에 AI 문항을 끼워 넣지 않는다. 카드에는 `AI 추가 연습 n회 · 정답 m회`를 따로 보여 주고, 기존 보충 문제로 계속 이동할 수 있게 한다.

## 생성 입력과 서버 경계

새 경로 `POST /api/practice`를 기존 Host·동일 출처 검사 아래 둔다. 기존 `/api/ai`의 수업 제안·일지 계약은 그대로 둔다. 서버의 Gemini HTTP 전송 부분만 별도 공통 모듈로 추출해 양쪽이 사용한다. API 키·모델 설정은 기존 서버 환경변수를 사용한다.

입력: `{ requestId, inputRevision, assessmentId, cardId, conceptId, baseQuestionId, evidence }`.

- `requestId`는 LAN HTTP에서도 동작하는 생성기를 사용한다.
- `evidence`는 등록된 진단·기존 보충 문항에서 같은 개념의 최근 최대 3개 `{ questionId, result, choiceId, helpUsed }`만 보낸다. 이름·메모·전체 저장 상태는 보내지 않는다.
- 첫 버전에서는 AI 생성 문항의 답변을 다음 생성의 프롬프트 근거로 보내지 않는다. 해당 답변은 추가 연습 기록과 중복 방지에만 쓴다. ‘더 연습’은 같은 기존 오답 근거로 새로운 식을 제안한다. AI 문항 응답을 다음 난이도 조절에 반영하는 일은 후속 범위다.
- 서버가 concept/base 문항의 고정 매핑과 등록된 선택지를 확인한다. 다른 개념, 미승인 문항, 임의 난이도·임의 지시는 거부한다.
- 브라우저 저장 기록이 사실임을 서버가 인증할 수 있다는 주장은 하지 않는다. 이 입력은 연습 맞춤화 참고이며 진단 증거를 대체하지 않는다.
- 모델에는 구조화된 문제 사양, 관찰된 선택, 허용 범위만 전달한다. ‘부호 오류가 원인’ 같은 확정 진단을 지시하지 않는다.
- 한 요청은 한 문항, 한 번의 모델 호출이다. 자동 재시도는 하지 않는다.

## 수학 계약과 검증

새 순수 모듈 `public/src/learning/linear-practice.js`를 서버와 브라우저가 함께 사용한다.

허용 식 구조:

- `{ type:'integer', value:n }`, `{ type:'variable' }`
- `{ type:'add'|'subtract', left, right }`
- `{ type:'scale', factor:n, expression }`

문자끼리 곱하기, 나눗셈, 거듭제곱, 함수 호출, 임의 문자열 수식은 허용하지 않는다. `eval`/`Function`을 사용하지 않는다. AST 최대 깊이 4, 최대 노드 32, 정수 리터럴 -12~12, scale 계수 -9~9, 최종 계수·상수 절댓값 50 이하로 제한한다. 정수 계산 결과는 모두 안전한 정수여야 한다.

AI 출력 사양: `{ version:1, conceptId, expression, options:[expr,expr,expr,expr], claimedAnswer:{a,b}, focus:'like_terms'|'distributive'|'minus_parentheses' }`.

- 모든 식을 독립적으로 `(a,b)`, 즉 `ax+b`로 환산한다. 문자 값을 몇 개 대입해 우연히 일치하는지만 보지 않는다.
- 정답 `(a,b)`가 claimedAnswer와 일치하고 네 선택지 중 정확히 한 개와 동치여야 한다.
- `(a,b)`가 같은 선택지 두 개는 표기가 달라도 중복으로 거부한다.
- `roadmap-like-terms`: 괄호 배분이 필요 없는 문자항·상수항 합차이며 같은 차수의 문자항이 2개 이상, 최종 a≠0이다.
- `roadmap-linear-sum`: 괄호 안 합차에 대한 정수배 또는 괄호 앞 뺄셈이 최소 하나 있고 최종 a≠0이다.
- 무의미한 0배, 문항/선택지 부족, 범위 초과, 허용되지 않은 focus는 거부한다.
- 발문·LaTeX·선택지·풀이 단계는 검증된 식에서 코드로 만든다. 모델의 자유 서술 해설은 출제에 쓰지 않는다.
- 문항 본문을 HTML로 해석하지 않고 기존 escape·KaTeX 렌더를 사용한다.
- 정규화한 식 구조와 선택지로 지문 식별값을 만들고 이미 노출된 문항과 같으면 자동 재호출 없이 기존 문제로 대체한다.

예: `2(x+3)−(x−1)`은 `(1,7)`이고, `x+7`과 `7+x`를 동시에 선택지로 주면 중복으로 거부한다. `3x+2x−4`의 정답은 `(5,-4)`다.

## 실패·취소와 동시 작업

생성 요청 전체 서버 제한 5초, 브라우저 제한 6초. 사용자는 대기 중 언제든 기존 문제로 이동한다. 기존의 공급자 15초 기본값이 새 경로 제한을 늘리지 않게 상위 deadline을 건다.

클라이언트의 동시에 실행 중인 요청은 1개다. 서버 새 경로는 동시 4개까지 처리하고 초과는 대기시키지 않고 기존 문항 대체로 돌린다. 완료·실패·취소 시 슬롯을 반드시 반환한다.

실패 대상: API 키/모델 없음, 잘못된 응답/JSON, 수학 검증 실패, 중복 문항, 차단/불완전 응답, 429, 네트워크 실패, 시간 초과. 실패 원문·키를 화면에 노출하지 않는다. 이유 코드는 기록할 수 있다.

역할·과목·학생·개념 이동, 초기화, 기존 문항 선택 시 요청을 취소하고 토큰을 무효화한다. 응답의 requestId, 당시 assessmentId/cardId, 화면 토큰, 입력 revision이 달라지면 저장·교체하지 않는다. 사용자가 이미 풀기 시작한 기존 문항을 늦은 AI 응답으로 바꾸지 않는다.

## 저장·채점과 기록 보존

공통 상태에 선택적 `generatedPractice` 배열을 추가한다. 없는 과거 저장본은 빈 배열로 읽으며 저장 키와 schemaVersion 1을 유지한다. 현재 진단의 attempts/roadmapPractice.attempts를 다시 쓰거나 재생하지 않는다.

각 레코드: `{ id, learnerId, assessmentId, cardId, baseQuestionId, question, requestId, inputRevision, generatedAt, validatorVersion, model, status, presentedAt, attempts }`.

- question은 `kind:'ai_generated'`와 생성 사양·표시 문제·계산된 정답·해설·지문 식별값의 스냅샷이다. 공식 기출 출처를 붙이지 않는다.
- status는 검증 완료 `ready`/제출 완료 `answered`만 저장한다. loading/error/취소 토큰은 화면 상태다.
- attempts는 `{ id, choiceId, result, abstained, helpUsed, answeredAt, evidence:'ai_review_practice' }`이며 같은 ID의 동일 제출은 무시하고 다른 답의 재제출은 거부한다.
- AI 문항 노출은 공통 exposures에도 `stage:'ai_review_practice'`로 남긴다. 실제로 화면에 제시되기 전에 저장된 것만으로 노출 처리하지 않는다.
- 새로고침 시 ready 문항을 이어서 풀고, answered 문항의 결과·해설을 복원한다. 현재 AI 연습 위치는 별도 선택 필드 `activeGeneratedPracticeId`로 저장하고, 닫거나 기존 문제를 선택하면 null로 둔다. 사용자가 한 번이라도 선택한 답은 제출 전에도 레코드의 선택적 `draftChoiceId`에 저장한다. 새 요청은 ‘더 연습’에서만 시작한다.
- 저장본 복원 시 생성 사양을 다시 수학 검증한다. 깨진 AI 레코드는 원본을 `recovery`에 보관하고 그 레코드만 사용 중지한다. 정상 진단/기존 기록 전체를 복구 불가로 만들지 않는다.
- `loadState`는 JSON 파싱 뒤, 전체 validateState 호출 **전에** AI 선택 필드만 복원·격리한다. 격리 원문은 선택적 `generatedPracticeRecovery`에 보관한다. 기존 필수 필드의 오류나 지원하지 않는 schemaVersion은 기존 복구 정책을 따른다. AI 필드 전체가 배열이 아니어도 그 값만 격리하고, 깨진 현재 문항 참조는 해제한다. 원래 저장 문자열은 사용자가 저장하기 전까지 덮어쓰지 않는다.
- 생성 기록은 기존 저장 revision 충돌 정책을 따른다. 다른 탭 변경은 덮어쓰지 않는다.

AI 연습 정답 수는 별도 집계하며 기존 최초 정답률·진단 티어·고졸 통과·새 문제 독립 적용률·일지의 실제 회기 시간에 합산하지 않는다.

## 최종 발표 검증 기준

1. 두 개념 모두 실제 Gemini 응답 → 코드 검증 → 풀이 → 기록 복원이 한 번 이상 성공한다.
2. 잘못된 정답, 동치 중복 선택지, 범위 밖 식, 잘못된 개념이 출제되지 않는다.
3. AI 미설정/429/시간 초과에서도 기존 문제로 연습·채점·저장이 가능하다.
4. 이동 후 늦은 응답, 연속 클릭, 새로고침이 중복 문항/답변을 만들지 않는다.
5. 과거 저장본과 현재 미커밋 변경을 보존한다. LAN HTTP 주소에서도 동작한다.
6. 실제 AI 설정이 없으면 모의 공급자 테스트와 기존 문항 대체까지 검증했다고 보고하며 실제 호출 성공으로 설명하지 않는다.
